### Задание 1

На лекции рассматривались режимы репликации master-slave, master-master, опишите их различия.

### Ответ

**Master-Slave (Primary-Replica)** — запись выполняется на основном сервере, реплика получает изменения из бинарного журнала и обычно обслуживает запросы чтения. При отказе основного узла переключение на реплику требует отдельной процедуры или механизма failover. При асинхронной репликации возможна задержка и потеря последних неподтверждённых на реплике изменений.

**Master-Master (двунаправленная репликация)** — оба сервера настроены как источники и реплики друг друга. Каждый может принимать записи, но одновременные изменения одних и тех же данных создают риск конфликтов. Обычная двунаправленная репликация MySQL не обеспечивает автоматическое разрешение конфликтов или failover.

| Критерий | Master-Slave | Master-Master |
|---|---|---|
| Запись | На основном узле | На обоих узлах (при осторожном распределении записей) |
| Чтение | На основном и реплике | На обоих |
| Направление репликации | Одностороннее | Двустороннее |
| Конфликты записи | Обычно отсутствуют | Возможны |
| Сложность | Ниже | Выше |

### Задание 2

Выполните конфигурацию master-slave репликации, примером можно пользоваться из лекции.

### Решение

**Подготовка:**

```bash
mkdir -p ~/mysql-replication/{master,slave,img}
cd ~/mysql-replication
```
Создаем `docker-compose.yml`:

```yaml
services:
  master:
    image: mysql:8.0
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: TempPass123!
    command: ["--server-id=1", "--log-bin=mysql-bin", "--binlog-format=ROW"]
    ports:
      - "127.0.0.1:3307:3306"
    volumes:
      - master-data:/var/lib/mysql
  slave:
    image: mysql:8.0
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: TempPass123!
    command: ["--server-id=2", "--log-bin=mysql-bin", "--relay-log=relay-bin", "--binlog-format=ROW"]
    ports:
      - "127.0.0.1:3308:3306"
    volumes:
      - slave-data:/var/lib/mysql
volumes:
  master-data:
  slave-data:
```

Запускаем контейнеры

```bash
docker compose up -d
docker compose ps
```
Пингуем и смотрим, что всё запущено.

```bash
docker compose exec master mysqladmin ping -uroot -p'TempPass123!'
docker compose exec slave mysqladmin ping -uroot -p'TempPass123!'
```
Включаем режим только для чтения на Slave:

```bash
docker compose exec slave mysql -uroot -p
```

