### Процесс настройки маршрутизатора

```text
enable
configure terminal
interface GigabitEthernet0/1
standby version 2
standby 1 ip 192.168.1.1
standby 1 priority 50
standby 1 preempt
standby 1 track GigabitEthernet0/0
end
write
```

## 1. Установка и настройка Keepalived
На обеих виртуальных машинах Linux (Ubuntu Server) был установлен сервис `keepalived` для организации плавающего IP-адреса по протоколу VRRP:
```bash
sudo apt update && sudo apt install -y keepalived
```
## 2. Настройка веб-серверов Nginx
На обеих ВМ в качестве веб-сервера был установлен и запущен `nginx`:
```bash
sudo apt install -y nginx
sudo systemctl enable --now nginx
```
* **VM1 (MASTER)** имеет физический IP: `192.168.1.110`
* **VM2 (BACKUP)** имеет физический IP: `192.168.1.108`

## 3. Bash-скрипт проверки доступности (Пункт 3 задания)
Был написан проверочный скрипт `/usr/local/bin/check_nginx.sh`. Он проверяет, слушает ли веб-сервер порт `80`, а также контролирует физическое существование главного файла сайта `index.html`. Если условия не выполняются, скрипт завершается с ошибкой (`exit 1`).

**Содержимое скрипта:**
```bash
#!/bin/bash

# 1. Проверяем доступность порта 80
ss -tuln | grep -q ":80 "
if [ $? -ne 0 ]; then
    exit 1
fi

# 2. Проверяем существование файла index.html
if [ ! -f /var/www/html/index.html ]; then
    exit 1
fi

exit 0
```
*Скрипт был сделан исполняемым на обеих машинах с помощью команды `sudo chmod +x /usr/local/bin/check_nginx.sh`.*

## 4. Конфигурация секции vrrp_script в Keepalived
### Конфигурационный файл `/etc/keepalived/keepalived.conf` для VM1 (MASTER):
```text
vrrp_script check_web {
    script "/usr/local/bin/check_nginx.sh"
    interval 3
}

vrrp_instance VI_1 {
    state MASTER
    interface enp0s3
    virtual_router_id 15
    priority 255
    advert_int 1

    virtual_ipaddress {
        192.168.1.15/24
    }

    track_script {
        check_web
    }
}
```

### Конфигурационный файл `/etc/keepalived/keepalived.conf` для VM2 (BACKUP):
```text
vrrp_script check_web {
    script "/usr/local/bin/check_nginx.sh"
    interval 3
}

vrrp_instance VI_1 {
    state BACKUP
    interface enp0s3
    virtual_router_id 15
    priority 200
    advert_int 1

    virtual_ipaddress {
        192.168.1.15/24
    }

    track_script {
        check_web
    }
}
```

## 5. Демонстрация переезда плавающего IP
### Тест 1: Штатный режим работы
При запуске служб плавающий IP-адрес `192.168.1.15` успешно привязывается к интерфейсу `enp0s3` первой машины (`MASTER`), так как её приоритет выше (255 против 200). Запросы пользователей по адресу `http://192.168.1.15` уходят на первый сервер.

### Тест 2: Эмуляция аварии (Переезд IP)
Для симуляции сбоя на машине `MASTER` был принудительно удален целевой файл веб-сервера:
```bash
sudo rm /var/www/html/index.html
```
Через 3 секунды скрипт `check_nginx.sh` завершился с ошибкой. Сервис Keepalived зафиксировал падение, автоматически снял плавающий IP `192.168.1.15` с первой машины и перенес его на вторую виртуальную машину (`BACKUP`). 

При обновлении страницы по адресу `http://192.168.1.15` в браузере, адрес остался неизменным, но контент начал отдаваться со второго (резервного) сервера, что подтверждает полную отказоустойчивость системы.
