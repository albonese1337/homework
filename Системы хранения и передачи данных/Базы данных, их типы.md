# Домашнее задание к занятию "`Базы данных, их типы`" - `Туркменов Роман`

### Задание 1. СУБД

### Кейс
Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать 
правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для
каждой предметной области. 

Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему? 
 
1.1. Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков.
СУБД должна гарантировать целостность и чёткую структуру данных.

### `Ответ`
Для бюджетирования проектов лучше использовать **реляционную СУБД**, например PostgreSQL.
Причины:
* строгая структура данных;
* поддержка транзакций ACID;
* контроль целостности;
* удобная работа с финансовыми отчётами через SQL.

---

1.1.* Хеширование стало занимать длительно время, какое API можно использовать для ускорения работы? 

### `Ответ`
Для ускорения хеширования можно использовать **GPU API**, например CUDA/OpenCL, если задача допускает параллельное выполнение вычислений.

---

1.2. Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к 
маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM? 
СУБД должны быть гибкими и быстрыми.

### `Ответ`

Для лендингов можно использовать документоориентированную NoSQL СУБД, например MongoDB, так как структура данных может часто меняться.
Для CRM лучше использовать реляционную СУБД, например PostgreSQL, поскольку данные о клиентах, сделках и менеджерах имеют связи между собой.

---

1.2.* Можно ли эту задачу закрыть одной СУБД? И если да, то какой именно СУБД и какой реализацией?

### `Ответ`

Да, можно использовать PostgreSQL.
Структурированные данные CRM хранить в обычных таблицах, а гибкие данные лендингов — в колонках типа `JSONB`.

---

1.3. Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу 
и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.

### `Ответ`
Подойдёт иерархическая или документоориентированная СУБД.
Например MongoDB, где документы и материалы можно хранить согласно структуре компании: подразделение → отдел → документы.

---

1.3.* Можно ли под эту задачу использовать уже существующую СУБД из задач выше и если да, то как лучше это 
реализовать?

### `Ответ`
Да. Можно использовать MongoDB из предыдущей задачи и создать отдельную базу или коллекции для корпоративных документов.

---

1.4. Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов 
по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать
со связями.

### `Ответ`
Лучше использовать Графовую СУБД, например Neo4j.
Она хорошо подходит для работы с большим количеством связей: объекты, склады, маршруты, курьеры и точки доставки.

---

1.4.* Можно ли к этой СУБД подключить отдел закупок или для них лучше сформировать свою СУБД в связке с СУБД 
логистов?

### `Ответ`
Отдел закупок можно подключить к общей системе, если данные тесно связаны с логистикой.
При этом данные закупок логично хранить отдельно, например в PostgreSQL, а необходимые данные передавать в графовую БД логистики.

---
1.5.* Можно ли все перечисленные выше задачи решить, используя одну СУБД? Если да, то какую именно?

### `Ответ`
Технически большую часть задач можно реализовать на PostgreSQL.
Он поддерживает:
* реляционные данные;
* JSON/JSONB;
* расширения;
* транзакции;
* сложные SQL-запросы.
Но в реальной системе лучше использовать несколько специализированных СУБД под разные задачи.

### Задание 2. Транзакции

2.1. Пользователь пополняет баланс счёта телефона, распишите пошагово, какие действия должны произойти для того, чтобы 
транзакция завершилась успешно. Ориентируйтесь на шесть действий.

### `Ответ`

1. Пользователь вводит номер телефона и сумму.
2. Система проверяет корректность данных.
3. Проверяется наличие необходимой суммы на банковском счёте.
4. Деньги списываются со счёта пользователя.
5. Баланс телефона увеличивается на указанную сумму.
6. Транзакция фиксируется (COMMIT), пользователь получает подтверждение.

Если на любом этапе возникает ошибка, выполняется `ROLLBACK`.

---


2.1.* Какие действия должны произойти, если пополнение счёта телефона происходило бы через автоплатёж?
### `Ответ`


1. Система автоматически проверяет условие автоплатежа.
2. Проверяет сохранённые настройки и способ оплаты.
3. Проверяет наличие денег.
4. Списывает необходимую сумму.
5. Пополняет баланс телефона.
6. Фиксирует транзакцию и отправляет уведомление пользователю.

### Задание 3. SQL vs NoSQL

3.1. Напишите пять преимуществ SQL-систем по отношению к NoSQL. 
### `Ответ`

Преимущества SQL:

1. Строгая структура данных.
2. Поддержка ACID-транзакций.
3. Контроль целостности данных.
4. Удобная работа со связями через `JOIN`.
5. Стандартный язык SQL для сложных запросов и аналитики.

---
3.1.* Какие, на ваш взгляд, преимущества у NewSQL систем перед SQL и NoSQL.
### `Ответ`

Преимущества NewSQL:

* поддержка ACID как у классических SQL-СУБД;
* горизонтальное масштабирование;
* распределённое хранение данных;
* высокая производительность;
* сохранение привычного SQL-интерфейса.

То есть NewSQL пытается совместить надёжность SQL и масштабируемость NoSQL.

### Задание 4. Кластеры

Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу 
выделено 1000 машин. 

На основе какого критерия будете выбирать тип СУБД и какая модель *распределённых вычислений* 
здесь справится лучше всего и почему?

### `Ответ`

Основной критерий выбора — возможность **горизонтального масштабирования и распределённой обработки больших объёмов данных**.
Для 1000 машин хорошо подходит модель **MapReduce**.

Принцип работы:
`Map` — большая задача разбивается на множество небольших задач и распределяется между узлами.
`Reduce` — результаты вычислений собираются и объединяются.
Такая модель позволяет использовать вычислительные ресурсы множества машин параллельно и подходит для обработки больших объёмов данных.
